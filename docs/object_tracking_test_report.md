# 객체 종류·추적·사용자 영상 테스트 보고서

영상·캡처·로그·환경 기록은 공개 저장소에 포함하지 않는다. 아래 경로는 로컬 재현 시 생성되는 위치다.

2026년 10월 8일, 사람·개 종류 선택, 실행 내 추적 번호, 객체별 쿨다운과 상태 저장을 구현했다.
최종 코드에서 6회 실행·2,381프레임·166장 저장을 확인했고 자동 테스트 106개와 pip check가 통과했다.
저장·로그 계약은 통과했지만 독립 정답 라벨이 없어 탐지 정확도와 물리적 개체 동일성의 성능 합격을 뜻하지 않는다.
사용자 요청에 따라 고정 카메라의 각 장면 안 동작을 평가하며 편집 장면 전환은 성능 평가에서 제외했다.

## 1. 구현된 기능

- `--classes person dog`: 모델 이름에서 종류 ID를 찾아 선택한다. 모델에 없는 이름은 오류로 알린다.
- `--track`: ByteTrack 기본, BoT-SORT도 선택 가능. 추적기에는 낮은 신뢰도 후보를 연결용으로 제공하지만 화면·로그에 노출되는 검출 및 저장에는 사용자 신뢰도 하한을 유지한다.
- 객체 변수: `ObjectStateStore.objects[track_id]`. 종류, 마지막 위치·신뢰도, 현재 관측 여부와 전경 판정, 처음/마지막 관측 시간, 저장 트리거 수를 관리한다.
- 종류와 원래 추적기 번호 조합으로 공개 `track_id`를 매핑해 종류가 다른 결과를 같은 변수에 섞지 않는다. 원래 번호는 `tracker_id`로 남긴다.
- `--capture-scope object`: 성공 저장을 발생시킨 번호마다 쿨다운을 관리한다. 기존 기본값은 추적 없이 사람 전용·전체 쿨다운이다.
- 여러 번호가 같은 프레임에서 저장 대상이면 원본 전체 JPG 한 장으로 묶고 `saved_track_ids`에 트리거 번호를 기록한다. crop 저장은 아니다.
- 추적 화면에서 상태 패널을 오른쪽에 표시해 원본 화면과 번호를 가리지 않는다. 원본 JPG에는 표시를 섞지 않는다.

추적 API는 [Ultralytics 추적 문서](https://docs.ultralytics.com/modes/track/)를 참고했다.
종류는 [모델의 COCO 목록](https://docs.ultralytics.com/datasets/detect/coco/#dataset-yaml)에서 선택하며 임의의 이름만 추가해 새 종류를 탐지할 수 있는 것은 아니다.

## 2. 실제 실행 결과

공통 조건: Mac Apple M1 CPU, YOLO11n, GUI 없이 fast, 매 프레임 로그, 영상 시간 기준 쿨다운 0.5초.
한 명 통행은 신뢰도 0.60·기준 전경 3000, 산책 및 사용자 영상은 신뢰도 0.40·기준 전경 1000·비율 0.03이다.
워밍업은 2초이며 imgsz 기본 640, 마지막 비교만 960이다. 각 실행은 전체 입력을 순서대로 처리했다.

| 테스트 | 프레임 | JPG | 처리 FPS | 생성된 실행 내 ID 수 |
| - | -: | -: | -: | - |
| 한 명 통행, 추적 | 369 | 17 | 23.36 | person: 1 |
| 한 명 통행, 기존 모드 | 369 | 17 | 25.06 | 추적 없음 |
| 공개 산책, 사람+개 | 271 | 110 | 16.17 | person: 34, dog: 46 |
| 사용자 3080, 야간 아기+개 | 258 | 8 | 18.23 | person: 3, dog: 3 |
| 사용자 5077, 야간 개 | 557 | 6 | 17.84 | dog: 4 |
| 사용자 5077, imgsz 960 비교 | 557 | 8 | 10.99 | dog: 4 |

**ID 수는 실제 사람·개 수가 아니다.** 같은 개가 가려지거나 재등장하면 새 번호를 받을 수 있고, 중복 탐지나 잘못된 연결도 가능하다.
공개 산책의 다수 ID는 혼잡·가림·카메라 움직임이 있는 영상에서의 불안정성을 보여준다. 해당 산책 결과는 종류·저장 기능 확인이며 고정 카메라 성능을 대표하지 않는다.

## 3. 사용자 영상별 평가

### tiktok-7675232379845283080.mp4

720×1280, 30 FPS, 258프레임·8.6초의 파일이다. 원본 전체 해상도를 유지했다.
사람과 개를 동시에 관측했고 8장의 저장 트리거는 모두 개였다. 사람 트리거는 0장이다.
아기 대표 `person #1`은 230프레임 관측됐고 저장 트리거는 0이다.
개는 2.37~3.40초에 3장, 6.17~8.27초에 5장 저장됐다.
현재 전경 조건은 누워 있는 아기와 움직이는 개를 구분하는 사례로 작동했다.
초기 워밍업에는 사람으로 분류된 중복 박스가 있어 총 3개의 사람 ID가 생겼다. 실제 사람이 3명이라는 뜻이 아니다.
개가 사라졌다 다시 나타나면 새 번호를 받았으며 같은 개의 영구 식별을 검증하지 않았다.

### tiktok-7622221281492045077.mp4

720×1280, 30 FPS, 557프레임·약 18.57초의 파일이다. 사람 없이 개만 관측했고 기본 추론 크기로 6장을 저장했다.
같은 파일에서 imgsz만 960으로 바꾸면 8장으로 늘고 개 관측 프레임은 167→178로 증가했다.
먼쪽 개의 첫 관측은 15.60→13.60초로 앞당겨졌지만 처리 속도는 17.84→10.99 FPS로 감소했다.
이 비교는 같은 영상에서의 탐색이며 독립 정확도 검증은 아니다. 빠른 동작의 흐림과 먼쪽 작은 개에서 탐지가 끊긴다.
영상에 검정 여백과 자막이 있어 실제 CCTV 영상이 차지하는 면적이 작다. 실사용 평가에서는 여백 없이 원본 카메라 파일을 사용하는 편이 대상의 세부 정보를 유지할 수 있다.

MOG2 전경과 박스의 겹침은 실제 이동 속도를 확정하지 않는다. 이 파일들의 CCTV 화면 시계는 영상 파일 시간과 다르게 진행하므로 로그의 시간·쿨다운은 MP4 파일 시간 기준이다.
정지·이동 구간, 모든 박스 및 동일 개체 정답을 독립적으로 라벨링하지 않아 precision/recall이나 IDF1은 산출하지 않았다.

## 4. 저장·번호 계약 검사

모든 최종 실행에서 전체 입력 처리, 매 프레임 로그, 선택 종류 제한, 종류별 ID 일관성,
워밍업 무캡처, 객체별 0.5초 쿨다운, 프레임당 JPG 한 장, 로그·실제 파일·요약 수 일치를 확인했다.
각 JPG의 바이트를 해당 입력 원본 프레임의 JPEG quality 95 재인코딩 결과와 비교해 모두 일치했다.
객체별 저장 트리거 수와 요약도 일치했다. 이런 계약 통과는 탐지 박스·ID 정확도 합격을 뜻하지 않는다.

한 명 통행 영상은 추적 번호 하나를 유지하며 17장을 저장했고 기존 모드도 17장이었다.
자동 테스트에는 종류 이름 조회, ID가 없는 결과의 처리, 서로 다른 종류를 동일 변수에 섞지 않기,
순서가 바뀌어도 상태 유지, 새 객체의 독립 쿨다운, 다수 객체의 JPG 묶음,
저장 실패 시 쿨다운 불변, 로그 종류 분리와 원본 배열 불변을 포함한다.

프로젝트 루트의 Mac 가상환경에서 실제 화면 테스트:

```bash
.venv/bin/python main.py --video "/원본/영상.mp4" --classes person dog --track --capture-scope object --cooldown-sec 0.5 --confidence 0.4 --min-object-motion-pixels 1000 --show-mask --debug-decisions
```

먼쪽 작은 대상 비교에는 `--imgsz 960`을 추가한다. 기존 기본값은 유지했다.
실행 뒤 `logs/<run_id>/summary.json`의 `objects`와 `captures/<run_id>/`를 확인한다.
기록한 모든 파일을 다시 시험하려면 `tools/run_tracking_tests.py --videos <파일1> <파일2> --compare-imgsz 960`,
저장 계약 및 표시 영상 재생성은 `tools/evaluate_tracking_tests.py`를 같은 Python으로 실행한다.
스크립트의 재실행은 새 run_id와 결과 파일을 생성하며 기존 원본 영상과 기존 캡처는 변경하지 않는다.

## 6. 출처와 검증 범위

한 명 통행은 CDnet 보행자 영상의 원본 프레임 730~1098을 연속으로 추출한 14.76초 파일이다.
전체 화면을 유지했으며 출처와 변환은 single_pass_manifest.json (`test_data/single_pass_manifest.json`)에 기록했다.
CDnet 변환본의 25 FPS는 시험용으로 지정한 타임베이스이고 원본 촬영 FPS를 검증한 값은 아니다.
공개 산책은 Nesnad의
[Pro dog walker - Tokyo - 2024 Nov 1](https://commons.wikimedia.org/wiki/File:Pro_dog_walker_-_Tokyo_-_2024_Nov_1.webm),
[CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/)이다. 원본 전체 디코드 271프레임을 유지하고 오디오를 제외해 MP4로 변환했다.
WebM 메타데이터는 272프레임을 보고했으나 독립 FFmpeg 디코드는 271프레임을 확인했다.
변환 정보 (`test_data/tracking_sample_manifest.json`)에 기록했다. 사용자 영상은 제공된 로컬 원본을 직접 읽었다.
표시용 결과 영상은 검증된 로그의 박스·번호·저장 상태와 재계산한 MOG2 마스크를 원본 프레임에 그린 진단용 MP4다.
라이브 실행 속도와 별개로 파일 FPS에 맞춰 재생되며 GUI 실행을 녹화한 것은 아니다.

이번 추적 시험은 Mac CPU 및 표시 이미지/결과 영상에서 확인했다. Windows와 변경된 추적 UI의 실제 창 조작은 별도 검증이 필요하다.
