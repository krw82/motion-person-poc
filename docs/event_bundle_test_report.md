# 사건 사진 묶음·Python 패키지 테스트 보고서

2026-10-08, macOS Apple M1 CPU, Python 3.12.14. 모델 YOLO11n과 기존 Ultralytics 8.4.174·OpenCV MOG2·ByteTrack·NumPy·lap을 유지했다.
사용자 입력 영상, 모델, 캡처와 실행 로그는 저장소/배포 패키지에 포함하지 않는다. 결과 파일 경로는 이 컴퓨터에 생성된 로컬 경로이며 재현 후 확인한다.

## 구현한 범위

- `MotionEngine.video(...).start()` / `MotionEngine.webcam(capture=True).start()`에 공통 프레임 분석·사건 캡처 엔진을 연결했다.
- 선택 객체+박스 내부 전경 조건으로 시작하고, 시작 전 최대 3초·약 0.5초 간격 후보·정지 후 맥락을 수집한다.
- 관련 판정이 3초 동안 없거나 전후 포함 10초에 도달하면 최대 6장을 골라 저장한다. 종료 대기가 사후 구간이고 다시 3초를 더 기다리지 않는다.
- 긴 관측은 동일 event_id의 다음 part로 이어간다. 추적 번호 변경이나 객체 종류 변경으로 사건을 나누지 않는다.
- 완료된 폴더가 공개된 뒤에만 on_event를 호출한다. 조기 알림·Gemini·사용자 규칙 판정은 구현하지 않았다.
- 원본 전체·박스 없는 JPG와 시각·좌표·객체 근거·종료 이유·맥락 부족 플래그를 저장한다. 화면 좌우 반전은 저장 사진에 영향을 주지 않는다.
- 압축 후보의 기본 보관 예산은 64 MiB다. 전체 모델/프레임 메모리의 한도는 아니다. EOF·종료·오류 처리에서 자원을 정리한다.
- 기존 루트 import와 main.py/간편 CLI 개별 캡처, 저장 없는 웹캠 명령을 호환 진입점으로 유지했다.

person·dog 선택, confidence 0.4, 기준 전경 픽셀 1000, 최소 전경 비율 0.03,

9개 입력 영상과 설치 환경 재검증을 합쳐 **5,386프레임·96장**을 검사했다.
모든 저장 JPG를 입력의 해당 프레임으로 JPEG quality 95 재인코딩한 바이트와 대조했고 전부 일치했다.
파일 수·요약·JSONL/manifest의 묶음 수, 10초 이하, 최대 6장, 시각 순서, 원본 해상도, 입력 EOF도 확인했다.

FPS는 모델 초기화·재생 대기·입력 대기·화면 표시를 제외한 분석/캡처/콜백 처리 시간 기준이며 단회 측정치다.
CDnet와 제어 영상 시간은 생성된 MP4의 할당 FPS 기준으로, 원 촬영 FPS를 검증한 값은 아니다.

### 정지 제어 영상 해석

이 입력은 처음 5초 배경, 5~10초 이동, 10~22초 같은 프레임 유지, 22~27초 재이동이다.
정지 구간에서 새 사건을 계속 만들지 않고 재이동 시 두 번째 사건 번호를 만들었다.
첫 사건은 길이 제한으로 2개 묶음이 되고 재이동은 1개 묶음이 됐다.
MOG2 전경 잔류는 정지 시각 10초 이후 **2.08초**, 첫 사건 수집 종료는 **15.08초**였다.
따라서 ‘실제로 멈춘 즉시 3초 뒤 종료’를 보장하지 않는다. 3초는 결합 판정의 마지막 조건 충족 시점 기준이다.
이 입력은 제어된 프레임 고정이며 자연스러운 정지/변하는 배경의 정확도 시험을 대신하지 않는다.
대표 사진에서 사람 정지·재이동·퇴장 후 빈 장면을 시각적으로도 확인했다.
로컬 사진 비교: `test_data/event_bundle_results/stop_resume_bundle.png`.

### 5396 영상 해석

전체 원본 640은 기존 시험과 마찬가지로 대상 탐지를 놓쳐 0개다. 올바른 정지 제외 결과로 평가하지 않는다.
이미 검증한 해당 영상의 카메라 영역 ROI+960을 설치된 패키지 API에 전달하니 1개 묶음·6장을 저장했다.
묶음 7.60초, QUIET 종료, 전후 맥락 플래그 complete=true, 원본 JPEG 6장 일치다.
이 ROI 값은 제공된 세로 영상의 여백 제거용이며 다른 카메라에 그대로 적용할 기본값이 아니다.
이 영상에는 개가 등장하며 아기 기어다니기 정확도 검증이 아니다.

## 실제 웹캠

실제 카메라 0에서 저장 없는 3초 시험은 45프레임 처리·저장 0장을 확인했다.
이어 저장 모드를 12초 실행했다. **216프레임·묶음 2개·사진 10장**,
처리 17.96 FPS, 입력 프레임 건너뜀 144개였다.

- 같은 사건 번호의 part 1/2: 10.00초/6장/MAX_DURATION、1.96초/4장/DURATION_LIMIT.
- 두 묶음 모두 폴더·사진·manifest 저장 후 콜백을 호출했다.
- 저장 JPG 10장을 실제 디코드하고 원본 해상도/요약/파일 수와 대조했다. 영상 시험과 달리 웹캠 원시 프레임을 별도로 저장해 바이트 비교하지는 않았다.
- 압축 후보 버퍼 최대 4,733,038바이트, 시간 제한 종료·카메라 해제 확인.
- 픽셀 저장은 local captures 아래만 이루어졌고 Gemini/외부 서비스 호출은 없다.
- latest-frame 입력이므로 오래된 프레임을 쌓지 않는다. 30 FPS 전체 프레임 추론을 보장하지 않는다.

웹캠 저장 위치: `captures/event_verified/webcam_live/20261008T083849611343Z_32fa2809`.
실제 카메라 입력·저장은 확인했지만, 이번 시험은 no-display로 실행해 변경된 실시간 GUI 창 조작은 확인하지 않았다.

## 설치된 패키지

`motion_person-0.2.0-py3-none-any.whl`을 임시 설치 폴더에 `--no-deps --target`으로 설치했다.
프로젝트 밖 작업 폴더에서 `python -I`로 실행해 checkout/PYTHONPATH를 제외하고,
호스트의 다른 `config` 모듈을 미리 주입해도 패키지 상대 import가 작동하는지 확인했다.
설치된 API로 CAVIAR와 5396 ROI 960을 끝까지 처리했고, 24장 모두 원본 JPEG 바이트와 일치했다.
설치된 CLI 도움말도 통과했다. wheel 구현 파일은 최종 checkout 파일과 바이트 일치를 확인했다.
가중치·입력 영상·테스트 데이터가 wheel에 포함되지 않는다.

테스트한 wheel SHA256: `3c7546b750bad9e08269c0d6d52488f10e39ce5d0d2981cc76f4bc49948d7efe`.
배포 파일: `dist/motion_person-0.2.0-py3-none-any.whl`. PyPI 업로드·GitHub 푸시는 이번 작업에서 하지 않았다.

## 남은 범위

기본 캡처 라이브러리는 구현·검증했다. 수 시간/수 일 감시, 실제 Windows, 카메라 재연결·디스크 보관 정책은 남아 있다.
독립 객체/행동 정답 주석은 없으므로 탐지 재현율, 개체 동일성, ‘책상 위에 올라감’·‘훔침’ 판단의 정확도를 주장하지 않는다.
QUIET와 사진 phase는 수집 판정이며 실제 사용자 조건의 해제나 행동 단계 정답이 아니다.
알림/자연어 규칙/Gemini는 이 패키지를 사용하는 프로젝트가 완료된 묶음을 받아 확장한다.
