# 리팩터링 구현 검증 결과

2026-10-12. 사용자의 요청에 따라 추가 테스트를 종료했다. 아래는 이미 완료한 검증이다.

- 전체 테스트: 256개 통과. FastAPI TestClient의 의존성 사용 중단 예정 경고 1개가 있었으며 실패는 없었다.
- 정적 확인: 변경된 구현과 연결 예제의 Ruff F 검사, Python 컴파일, git diff --check 통과.
- React 프로덕션 빌드 통과. JavaScript gzip 약 71.7 KiB. 프론트는 Python wheel에 포함하지 않는다.
- 실제 CAVIAR 동영상: 725프레임, 사건 2개, 묶음 3개, 원본 사진 18장. 영상 완료 확인 및 종료 상태의 비활성 갱신 확인.
- React의 서버 MJPEG 이미지 디코딩과 사건별 사진/품질 표시 확인. Streamlit에서도 같은 실행의 사진 조회 확인.
- 기존 개별 캡처 CLI: 같은 영상 725프레임, 사진 15장, 실패 0건, END_OF_VIDEO. 기존 저장 정책을 유지했다.
- wheel 빌드 및 포함 범위 확인: 역할별 패키지와 py.typed 포함, 웹 예제·모델·영상·테스트 제외. 검증 당시 wheel 약 111 KiB, Python 소스 약 279 KiB.
- 새 가상환경에 NumPy·OpenCV와 wheel만 설치하여 자체 탐지기 주입으로 실제 영상 25프레임 처리. torch·Ultralytics·FastAPI·Streamlit 없이 기본 패키지 동작 확인.

회귀 검증은 진단/미리보기 오류 격리, 인터럽트의 완료 묶음 회수, 2장 사진의 모션 증거 보존,
사전·사후 관측 누락 표시, 추적 상태 상한/만료와 ID 재사용 방지, 여러 시청자의 JPEG 공유,
호스트 단일 실행과 분석 대기열 초과/외부 분석 오류를 포함한다.

종료 후 수집 중 표시가 남는 문제는 마지막 프레임의 event_active 값이 최종 상태에 남는 것이 원인이었다.
영상 종료·시간 제한 회귀 테스트가 수정 전 실패하고 수정 후 통과했다. 종료 시 event_active=False를 반영했고,
실제 영상 재실행에서도 비활성 상태를 확인했다.

Gemini 유료 네트워크 호출, 실제 연결 프로젝트 통합, 웹캠 장시간 운용과 Windows 운용은 이번 검증 범위에 포함하지 않았다.
Gemini SDK와 장기 이력은 핵심 패키지에 추가하지 않았다. 연결 프로젝트의 분석 함수를 호스트에 주입해야 한다.
모델의 torch 메모리와 추론 비용은 남으며, 사진 버퍼 상한은 전체 프로세스 메모리 한도가 아니다.

실행 방법은 [FastAPI·React·Streamlit 안내](../examples/fastapi/README.md), 구조는 [아키텍처 안내](architecture.md)를 참고한다.
