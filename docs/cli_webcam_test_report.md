# 간편 CLI·웹캠 미리보기 테스트 보고서

검증일: 2026-10-08. 환경: macOS / Apple M1 CPU, Python 3.12.14,
OpenCV 5.0.0.93, NumPy 2.5.3, Ultralytics 8.4.174, lap 0.5.13.

## 실행 방법과 기본 동작

모듈 폴더에서 `./motion`을 실행하면 웹캠, 영상, 설치 확인 메뉴가 나온다.
`./motion webcam`은 선택 객체의 박스·추적 번호와 움직임 여부를 표시하며
사진·영상·실행 로그를 저장하지 않는다. `./motion video "경로"` 또는
`./motion "경로"`는 기존 파일 분석기를 호출해 원본 JPG와 로그를 저장한다.
영상의 기본 설정은 사람, 안정 추적, 객체별 최소 0.5초 간격, 신뢰도 0.4,
기준 전경 면적 1000픽셀이다. `--objects 사람 개`로 대상을 함께 선택할 수 있다.
`./motion doctor`는 설치 상태와 모델 파일 존재를 확인하며 카메라를 열지 않는다.

한글·공백 경로, 경로를 묻는 입력란의 따옴표 및 Finder 이스케이프,
홈 경로를 지원한다. 시작 안내에는 대상·입력·저장 위치가 표시되고,
잘못된 입력에는 한국어 설명과 도움말 명령을 표시한다.
기존 `main.py` 옵션·기본값·로그 형식은 유지한다.

## 자동 테스트

```bash
.venv/bin/python -m pytest tests -q
```

**157개 통과.** 기존 117개, 웹캠 경로 9개, 간편 CLI 31개다.
CLI 시험은 실제 기존 설정 파서로 설정 전달을 확인한다. 사용자 입력 경로,
다른 작업 폴더에서 실행, 메뉴 선택·종료·입력 중단, 한국어 대상 별칭,
존재하지 않는 파일·모델, 잘못된 숫자·옵션, 의존성 부재, 읽기 전용 설치 확인,
종료 코드 전달과 기존 오류 출력 호환성을 확인했다.
카메라와 추론 실행은 CLI 자동 테스트에서 대체하며 모델·영상을 다운로드하지 않는다.
웹캠 시험은 최신 프레임 교체·중복 처리 방지·읽기 실패 시 해제,
움직임 유무 표시와 이미지·로그 미저장을 확인한다.

## 실제 영상으로 간편 명령 실행

CDnet 한 명 통행 샘플을 `test_data/cli_smoke/다른 실행 폴더/한 사람 통행 영상.mp4`로 복사했다.
이 폴더를 작업 위치로 삼아 모듈의 `motion` 실행 파일에 **경로만** 전달하고
`--no-display --fast --output ... --log-dir ...`를 추가했다.
모델 경로를 별도로 입력하지 않고 모듈의 모델을 정상적으로 찾았다.
분석 명령의 종료 코드는 0이며 `END_OF_VIDEO`와 입력 완료 검증이 기록됐다.

| 항목 | 결과 |
| - | - |
| 입력 | 360×240, 25 FPS, 369프레임 |
| 처리 / 읽기 | 369 / 369프레임 |
| 추적 결과 | 실행 내 사람 번호 1개, 관측 214프레임 |
| 움직임 조건 충족 | 212프레임 |
| 저장 성공 / 실패 | 17 / 0장 |
| 저장 시간 | 영상 시간 4.24~12.56초 |
| 같은 번호의 실제 저장 간격 | 모두 0.52초 |
| 처리 FPS | 26.307 (이 파일·설정의 CPU 측정값) |
| 전체 실행 시간 | 약 16.73초, 모델 준비 포함 |

0.5초 간격을 25 FPS 프레임 단위로 적용하면 다음 저장 가능 프레임은 13프레임 뒤이므로
이번 저장 간격은 0.52초였다. 저장 JPG 17장 모두 원본 해당 프레임을 JPEG 품질 95로
직접 인코딩한 바이트와 일치했다. 탐지 박스·상태 문구가 캡처에 들어가지 않았고,
로그 저장 수와 실제 JPG 파일 수가 일치했다.

로컬 결과는 다음 위치에 있으며 Git에 포함하지 않는다.

- 검증 기록: `test_data/cli_smoke/result.json`

- 로그: `test_data/cli_smoke/logs/20261008T060849827156Z_9d54943d/`

## 아직 확인하지 못한 범위

macOS에서 실제 웹캠 연결을 시도했으나 OpenCV가 카메라 권한 부재를 반환했다.
실제 카메라 프레임·창 표시와 처리 지연은 실행 앱에 권한을 허용한 후 확인해야 한다.
웹캠 실패 시 정리·오류 처리는 확인했으며 사용자 카메라 영상은 저장하지 않았다.
Windows 런처 `motion.cmd`는 제공했지만 실제 Windows 실행은 검증하지 않았다.
RTSP·카메라 재연결·장시간 운용과 객체 동일성의 정확도 평가는 별도 범위다.
작은 공개 파일의 처리 FPS를 실제 웹캠 성능으로 일반화하지 않는다.
