# 5396 영상: 개의 자세 변화와 움직임 캡처 시험

영상·캡처·로그·환경 기록은 공개 저장소에 포함하지 않는다. 아래 경로는 로컬 재현 시 생성되는 위치다.

2026년 10월 8일. 사용자가 누워 있는 아기는 캡처 대상에서 제외해도 된다고 정정했으므로,
기존 **선택 객체 탐지 AND 객체 박스 내부 MOG2 전경** 기준을 유지했다.
정지 객체를 주기적으로 저장하는 기능은 추가하지 않았다. 실행 코드·모델·라이브러리 변경 없이
기존 CLI 설정 세 가지로 같은 입력 전체를 처리했다.

## 입력과 조건

- 사용자 원본 (`videos/tiktok-7605040600257285396.mp4`): 720×1280, 30 FPS, 603프레임, 20.1초.
- 이 파일에서 확인한 대상은 개이며 아기는 등장하지 않는다. **아기 기어다니기 시험 결과는 아니다.**
- YOLO11n, CPU, Ultralytics 8.4.174, OpenCV MOG2, ByteTrack stable.
- person·dog 선택, confidence 0.4, 기준 전경 픽셀 1000, 최소 전경 비율 0.03,
  초기 배경 학습 2초, 관측 확인 3회, 객체별 캡처 간격 0.5초, 추적 유지 60 업데이트.
- 카메라 ROI는 이 입력에 맞춘 `(0, 0.34, 1, 0.66)`, 원본 픽셀 `(0,435,720,845)`,
  분석 크기 720×410이다. 자막·검은 여백을 제외한다. 다른 카메라에 그대로 적용할 값은 아니다.
- 분석 면적에 따른 실제 전경 픽셀 하한은 원본 전체 1778, ROI 570으로 보정된다.
  ROI 비교에서는 모델에 보이는 객체 크기와 전경 면적 기준이 함께 달라진다.
- 저장 JPG는 ROI를 적용해도 원본 전체 720×1280이고 박스·글자가 없다.
- 장면 전환은 사용자 요청대로 성능 판단에서 제외했다. 구간 안에서 대상 관측·자세 변화를 확인했다.

## 실제 결과

| 설정 | 개 관측 프레임 / 603 | JPG | 처리 FPS |
| --- | ---: | ---: | ---: |
| 전체 원본 / imgsz 640 | 0 | 0 | 20.87 |
| 카메라 ROI / imgsz 640 | 97 | 3 | 26.17 |
| 카메라 ROI / imgsz 960 | 479 | 4 | 13.44 |

모든 실행에서 사람 관측은 0프레임이다. CPU 속도는 단회 측정치이며 GUI 없이 모든 프레임을
순서대로 처리한 값이다. 원본 30 FPS와 같은 속도로 처리했다고 주장하지 않는다.

- 전체 원본 640: 신뢰도·추적 조건을 통과한 개 박스가 없어 0장이다. 정지 상태를 잘 걸러서
  0장이 된 결과가 아니라 **대상을 놓친 결과**다.
- ROI 640: 개를 97프레임에서 관측하고 한 번호 DOG #1로 3장 저장했다.
  시각은 6.633, 7.133, 7.633초다. 관측 공백이 많다.
- ROI 960: 첫 고정 카메라 구간의 프레임 0~478을 모두 DOG #1로 관측했다.
  이 전체 479프레임의 연속 관측은 로그로 별도 검증했다. 6.167, 6.667, 7.167, 7.667초에 4장 저장했다.
  나머지 관측된 구간에서는 전경 조건을 만족하지 않아 저장되지 않았다. 같은 구간의 대상 탐지는
  640보다 안정적이지만 처리 속도가 26.17→13.44 FPS로 줄었다.
- 뒤에서 방석에 누운 개는 두 ROI 설정 모두 탐지하지 못했다. 이 구간의 저장 0장은
  **탐지한 정지 개를 올바르게 제외했다는 근거로 사용할 수 없다.**

## 냉정한 평가

현재 파이프라인은 대상이 탐지될 때 박스 내부의 전경 픽셀·비율을 계산하고 조건을 충족하면 저장한다.
이번 4장은 걷기보다 같은 자리에서 고개·상체의 자세가 바뀌는 구간에 해당한다.
MOG2 전경은 실제 이동 속도나 행동 분류가 아니며, 자세 변화 뒤 배경이 적응하는 동안에도
전경이 남을 수 있다. **걷기·기어다니기만 골라 저장하거나 고개 움직임을 제외하는 기능은 현재 없다.**

검은 여백이 많은 세로 영상의 작은 개는 원본 해상도가 720×1280이어도 YOLO 입력에서 작아진다.
따라서 “아무 영상이나 해상도와 무관하게 같은 정확도”라는 보장은 할 수 없다.
이 파일에서는 카메라 ROI + imgsz 960이 앉아 있는 개의 관측에 가장 나았고,
누운 자세의 탐지와 30 FPS 처리 속도는 해결되지 않았다. 독립 박스·정지/이동 정답 주석은 없으므로
정확도, 재현율, 개체 ID 정확도의 수치를 제시하지 않는다.

객체별 0.5초 간격, 미확정 객체·워밍업 무캡처, 종류별 ID 일관성, 진단 영상 프레임 수를 검사했다.

## 직접 실행

프로젝트 디렉터리에서 다음 명령을 실행한다. 실제로 비교한 ROI 960 조건이고 GUI를 표시한다.
`--pace realtime`은 처리에 여유가 있을 때 원본 속도에 맞춰 기다리는 옵션이며 30 FPS 처리 보장이 아니다.

```bash
.venv/bin/python main.py --video videos/tiktok-7605040600257285396.mp4 --model models/yolo11n.pt --classes person dog --track --capture-scope object --cooldown-sec .5 --confidence .4 --min-object-motion-pixels 1000 --pace realtime --capture-dir captures/crawling_test/tiktok_7605040600257285396_roi_imgsz960 --log-dir logs/crawling_test/tiktok_7605040600257285396_roi_imgsz960 --roi 0 .34 1 .66 --imgsz 960
```

ROI 960에서 DOG #1 자세 변화 캡처, 7.17초 (로컬 파일: `test_data/tiktok_7605040600257285396_test/tiktok_7605040600257285396_roi_imgsz960_frame_215.png`)
